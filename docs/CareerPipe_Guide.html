CareerPipe: Career CI/CD

Setup, LLM keys, demo walkthrough and extension guide

1. What it is

CareerPipe treats a career like a codebase. A target role is a test suite, skill gaps are failing tests, the roadmap is the fix list, the mock interview is the integration test, the skill passport is the release tag, and changing your goal is a branch.

A visible council of agents (Strategist, Pedagogy, Time Budget, Arbiter) debates the plan. Every handoff is logged in the UI. All agents work without any LLM; an LLM only enriches wording and generates fresh questions.

2. Setup

  1. Install Python 3.10 or newer.
  2. Open the project folder in a terminal.
  3. Windows: run run.bat. Mac/Linux: run ./run.sh. This creates a virtual environment, installs requirements.txt and starts the server.
  4. Open http://localhost:8000.

Manual setup:

python -m venv .venv
.venv\Scripts\activate          (Mac/Linux: source .venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env          (Mac/Linux: cp .env.example .env)
uvicorn backend.main:app --reload --port 8000

Run the tests with pytest -q tests. Tests use a temporary database and never touch your learner data.

Learner data is stored in backend/data/learners.json. Set CAREERPIPE_DB to use a different file (for example for a clean demo).

3. Turning the LLM on

Edit .env, set LLM_PROVIDER and the matching key, then restart the server. The header badge shows the active provider. On any error (bad key, quota, network, invalid JSON) the agents silently fall back to rules, so the demo cannot break.

Provider.env settings
mock (default)LLM_PROVIDER=mock. No key needed.
Groq (free, open-source Llama)LLM_PROVIDER=groq, GROQ_API_KEY=... (key from console.groq.com), optional GROQ_MODEL
OpenRouter (free ":free" models)LLM_PROVIDER=openrouter, OPENROUTER_API_KEY=..., optional OPENROUTER_MODEL
GeminiLLM_PROVIDER=gemini, GEMINI_API_KEY=..., optional GEMINI_MODEL
OpenAILLM_PROVIDER=openai, OPENAI_API_KEY=..., optional OPENAI_MODEL
AnthropicLLM_PROVIDER=anthropic, ANTHROPIC_API_KEY=..., optional ANTHROPIC_MODEL
Ollama (local)LLM_PROVIDER=ollama, OLLAMA_URL=http://localhost:11434, OLLAMA_MODEL=llama3.1
Never commit .env. It is listed in .gitignore.

Shortcut: on the onboarding screen, click Guided demo (Asha story). It onboards Asha, verifies Python and SQL, fails React (JavaScript refresher), and adds project evidence in one click.

4. Five-minute demo walkthrough

  1. Onboard. Name "Asha", goal Full Stack Developer, claim Python, SQL and HTML. The pipeline shows the failing tests: JavaScript, CSS, Git, REST APIs, Testing, React, Node.
  2. Council. Open the agent log. Strategist puts JavaScript first because it unlocks React and Node. Pedagogy and the Arbiter merge this into a dependency-safe order.
  3. Verify, don't trust. Open the quiz and answer Python, SQL and HTML. Claimed skills turn into verified tests only after evidence.
  4. Root-cause re-plan. Use "simulate fail" on React. The Mentor inserts a JavaScript refresher instead of repeating React.
  5. Goal switch (branch). Change the goal to Backend Engineer. SQL stays green; the roadmap is recomputed and logged.
  6. Mock interview. Answer one technical question and one HR question. The behavioral average gates the hire decision.
  7. Why I would not hire you. The review shows REJECT with reasons, then the exact fixes that flip it to HIRE.
  8. Skill passport. Print or save as PDF. Only skills that passed are listed, with evidence and a disclaimer.
  9. Skill decay. Simulate 180 days without practice and watch verified skills fade and the plan adjust.
  10. Project evidence and deep-dive. On the pipeline view, paste a project description for a skill; 6/10 or more counts as proof. Then choose "Project deep-dive" in the interview to be asked about your own project.
  11. Career matching, timeline, explain. The pipeline view ranks every role by match with a one-click branch switch, charts job match over time, and "Explain my score" shows the quiz, interview and evidence behind any skill. A "Refresh due" banner flags skills going stale.
  12. Job match. On the Review & release tab, paste a real job posting and click "Match me". It shows verified, claimed-only and missing skills with one-click tests.
  13. Resume from proof. On the Review & release tab, click "Write resume bullets". Bullets use only verified skills, accepted project evidence and listed certifications.
  14. Organisation. Click "Load demo cohort" to see the cohort dashboard and paste a syllabus into the gap analyzer.

5. How assessment works

  • Each skill has several multiple-choice questions that rotate, so repeat attempts see new questions.
  • Quiz evidence uses the last 5 answers, recency-weighted. Interview scores use the last 3 answers.
  • Proficiency blends 40% quiz and 60% interview. A skill passes at 60%. One wrong answer does not fail a skill if the blended score still passes.
  • Hire decision: role match at least 80% and a behavioral (HR) average of at least 5/10.
  • Verified skills decay with a half-life of 120 days; skills idle 30+ days or below the bar show a refresh-due banner.
  • Project evidence scores concrete detail out of 10 (rule-based, enriched by the LLM); 6/10 or more verifies the skill at a 62% floor, lower than a full quiz plus interview.
  • Certifications and projects in the profile add the skills they mention as claims to verify.

6. Adding roles, skills and questions

No code change is needed. Edit the JSON files in backend/data/.

skills.json

"skills": { "docker": { "name": "Docker", "prereqs": ["git"], "weeks": 2,
            "aliases": ["containers"], "resources": [ ... ] } },
"roles":  { "devops": { "name": "DevOps Engineer", "skills": ["git","docker","api"] } }

questions.json

Every skill needs one entry with a primary question, two extra questions and an interview prompt:

"docker": {
  "mcq": {"q": "...", "options": ["A","B","C"], "answer": 1},
  "more": [ {"q": "...", "options": ["A","B","C"], "answer": 0},
            {"q": "...", "options": ["A","B","C"], "answer": 2} ],
  "interview": {"q": "Explain ...", "keywords": ["image","container","layer"]}
}

answer is the zero-based index of the correct option. Interview answers are scored on keyword coverage and structure.

7. Troubleshooting

ProblemFix
python not found on WindowsUse py instead, or reinstall Python with "Add to PATH".
Port 8000 busyRun uvicorn with --port 8001.
Badge shows mock though a key is setCheck spelling in .env and restart the server.
Want a clean demoStop the server and delete backend/data/learners.json, or start with a fresh CAREERPIPE_DB.
